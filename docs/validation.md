# Delivery validation

The implementation has focused acceptance tests under `packages/correctly/tests/public` and distribution checks under `tests/private`. Run `pnpm test` with loopback HTTP access. Tests use fixed repository fixtures and local HTTP servers; they do not depend on the original sibling repositories or external services.

| Acceptance                                         | Evidence                                                                                                                                                                                                                                       |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One external association in CI and editor          | Live stdio LSP/CLI parity tests plus property/value completion and hover tests; example documents have no embedded schema link.                                                                                                                |
| Useful consistent locations                        | Syntax, duplicate-key, schema type/enum, required and disallowed-property tests compare CLI and LSP ranges/pointers.                                                                                                                           |
| Local/remote references, identifiers and fragments | Draft 7 relative files, named configured resources, pointer/anchor associations, nested resources, 2020-12 dynamic references, and loopback HTTP graphs.                                                                                       |
| Offline and bounded requests                       | Offline reuse and misses, conditional refresh, stale-cache refusal on HTTP failure, byte/time/redirect/resource limits.                                                                                                                        |
| Unsupported/missing schemas                        | Unsupported drafts/required vocabularies, mixed drafts, invalid schemas/keywords, unresolved references, missing schemas and configs return visible failures.                                                                                  |
| Precedence and independent roots                   | Last-match-wins, explicit syntax-only coverage, config-relative paths, exclusions, nested configs, multiple roots and folder changes.                                                                                                          |
| Unsaved edits, refresh and stale results           | Unsaved data/schema tests, saved-only executable configs, imported extension reload and missing-import recovery, watched changes, outside-root schema watchers, rapid edits, delayed validation and cancellation before schema loads complete. |
| Real repository configurations                     | Lasertag/Wayforge/Recoverage Changesets configurations against the actual 2020-12 schema; Lasertag/agents.yaml dprint configurations against the official draft 7 schema. Invalid variants fail.                                               |
| Single CI command and exit codes                   | Spawned CLI tests parse pure JSON stdout and check exits 0/1/2 without filtering.                                                                                                                                                              |
| Adapter composition                                | Custom value models, exact numeric lexemes, adapter identity caching, missing hint capabilities, cleanup and compatibility failures.                                                                                                           |
| Installable extension                              | VSCE packages a universal VSIX; distribution tests run its staged server in an isolated directory without node_modules and check diagnostics/completion/hover.                                                                                 |

Final verification uses `pnpm fmt`, `pnpm check`, `pnpm test`, `pnpm build`, `pnpm build:vsix`, `pnpm build:zed`, and `pnpm test:distribution`. The example CLI command validates JSON, JSONC, YAML, and TOML successfully. Editor archives are inspected to confirm their manifests and bundled servers are present.

Zed distribution checks extract the shareable archive, verify the four language registrations and opt-in activation, and require a WASM component with the pinned Zed API version and no Cargo manifest or Rust library declaration. Tests recover the embedded server and worker bytes from that component and run them in an isolated directory without server npm dependencies. They cover unsaved edits in every supported format, dynamic watcher registration, JSON completion/hover, and saved schema/configuration refresh. Interactive sideload activation in a running Zed GUI is not automated here.

The VSIX has been packaged and its bundled stdio server exercised. Interactive extension activation in a running VS Code GUI is not automated here. Built-in VS Code JSON features remain independent and can be disabled as documented. Validation supports JSON/JSONC, YAML, and TOML; completion and hover support JSON/JSONC. Public format tests cover scalar semantics, aliases, nested source locations, numeric lexemes, custom validator composition, duplicates, unsupported values, default discovery, explicit parser selection, report version 2, and worker-backed CLI/LSP parity and saved-only configuration reloads. Distribution tests exercise both factories through the built CLI and an isolated VSIX project worker.
