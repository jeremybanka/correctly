# pklr WASM build

Correctly embeds the evaluator from [jdx/pklr](https://github.com/jdx/pklr) at commit `5084552234a7e5f8a691df61d80b4141cea84f4f`. This commit supplies synchronous, host-provided IO and `eval-core`; it is after the 4.0.0 release and is pinned rather than tracking upstream. The source archive is verified against SHA-256 `c8feacc200ea0cac7eb16fb83f60affd3072a0aae79ce337ae156f6c05da0932` before extraction.

`inherited-types.patch` preserves inherited module type annotations through amendments and checks overridden values against their inherited constraints, including through multiple amendments. It also rejects overrides of inherited immutable properties at every amendment or extension layer, including intermediate modules evaluated as bases. The public PKL tests protect these behaviors; remove the patch only after an upstream revision passes those regressions.

The Rust bridge is build-only code required to compile pklr. Correctly's source adapters, IO, build orchestration, and fixtures use TypeScript. The bridge disables native filesystem and HTTP capabilities and has no WASI or JavaScript imports. It receives source text and host resource results as JSON. Missing resources return requests to the TypeScript host, which loads them and reruns evaluation. Each pass uses a fresh WASM instance, avoiding stale state across documents or concurrent validations. Package extraction happens in memory.

The workspace's Mise configuration pins Rust and includes the `wasm32-unknown-unknown` target. Run `pnpm build:pkl` to rebuild the checked-in assets. The TypeScript build script downloads pinned sources into `artifacts`, applies the patch, uses `Cargo.lock`, remaps build paths, and writes `packages/correctly/src/core/pklr.wasm` and its dependency license notices. The TypeScript compiler wrapper derives metadata identifiers for every crate from its package/version, crate name, logical target and features, and remaps generated build-script output paths. Normalizing just path dependencies is insufficient across ARM and x86 build hosts. Compiler output is cached under a hash of the wrapper so changing this recipe cannot reuse objects compiled with older identifiers. `tar` and `patch` are build prerequisites.

`pnpm test:pkl` reproduces and compares both assets without updating them. A dedicated CI job runs this command on x86 and ARM Linux; distribution packaging has its own job. A mismatch exits unsuccessfully and saves expected/actual binaries and notices under `artifacts/pkl-reproducibility` for CI to upload. Successful checks remove evidence from earlier failures. Changes to upstream, the patch, the bridge, or the Rust lockfile require rebuilding the checked-in artifacts. Consumers and ordinary TypeScript builds require no Rust toolchain, source download, or external Pkl installation.

`pnpm exec node scripts/pkl-fixtures.ts` reproduces the compressed ZIP fixture in `packages/correctly/tests/public/fixtures/pkl`. It contains `Config.pkl` importing `nested/Value.pkl`, allowing package and relative import tests without a network service.
